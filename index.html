A score shown on your screen is not a prize claim.

Local storage, JavaScript variables, timers, network calls, and game-over messages can all be changed in a browser. GoGames therefore separates ordinary play from reward-bearing play. Existing games stay fun and unrestricted, but only a registered server-authoritative verifier can create a claim. The first implementation is math-sprint-v1.

Trust Boundary
What changed under the hood.
The reward pipeline is intentionally separate from normal game pages and their JavaScript scores.
🔐
Signed identity
Reward endpoints require a short-lived identity token signed by the server-side account system.
🧮
Server-owned scoring
The player sends inputs, not a score. The verifier creates challenges and calculates the outcome.
🧾
Compliance profile
Age, identity, sanctions, self-exclusion, terms, risk, and jurisdiction are managed outside the browser.
🔁
Idempotent claims
A verified session creates one claim. Repeated finish or payout requests cannot mint duplicates.
👤
Manual approval
Even a qualifying verified score remains pending until a compliance operator approves it.
📡
Signed payout handoff
Live mode dispatches an HMAC-signed request with an idempotency key to a separate payout service.
Reward Flow
No shortcut from score to prize.

Authenticate

The account service signs a short-lived reward identity.

Check eligibility

The server evaluates the current compliance profile and jurisdiction allowlist.

Play server challenge

The server owns every question, answer, timestamp, and session state.

Create one claim

The server calculates score, limits, integrity hash, and qualification.

Review and pay

An operator approves; only live mode can call the signed payout webhook.

GGX Utility Credits

Utility credit is separate from rewards.

Purchased GGX may pay for approved platform services and premium features. It is non-withdrawable, is not a cash balance, and does not make a player eligible for a reward program. Reward claims use the separate server-verification and compliance pipeline.

💳 View GGX PackagesRead Reward Rules
Reward availability depends on configuration, jurisdiction approval, identity and age verification, risk controls, terms acceptance, and manual review. No reward is promised merely because a game displays a high score.
