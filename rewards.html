Server verification + compliance gate

A browser score is never a prize claim.

GoGames keeps ordinary game play separate from reward-bearing play. A game page may display a score, winner, streak, or leaderboard position, but none of those browser values can create or settle a reward.

Existing games are practice/entertainment unless a server verifier explicitly says otherwise.
Chess rooms, arcade scores, FieldKit games, and browser-hosted AI battles cannot trigger payouts. Their JavaScript and network traffic are controlled by the player.

The trust boundary

1. Signed identity

The authenticated account service issues a short-lived token. A player cannot choose another reward identity in the request body.

2. Compliance profile

Age, identity, sanctions, self-exclusion, account restrictions, terms, device risk, and jurisdiction are controlled server-side.

3. Server challenge

The verifier creates the challenge and privately stores the answer or authoritative game state.

4. Server score

The player submits inputs only. The finish endpoint accepts no score, prize amount, or winner supplied by the browser.

5. One claim

A completed session can create exactly one idempotent claim with an integrity hash and audit record.

6. Human approval

A qualifying claim remains pending until a compliance operator approves it. Live payout is a separate signed service call.

First supported verifier

math-sprint-v1 is deliberately small and auditable. The server generates each arithmetic question, timestamps each answer, rejects impossible answer cadence, calculates correctness and elapsed time, applies the threshold and daily cap, then creates a reviewable claim.

This does not make Snake, Tetris, ChronoQuest, or any other browser game reward-safe. Each future reward game needs its own server-authoritative rules adapter.

What must pass

  1. Reward service is safely configured and not in off mode.
  2. Signed identity is valid, unexpired, and within the maximum token lifetime.
  3. Age and identity are verified.
  4. Sanctions check is clear; account is not restricted or self-excluded.
  5. Required terms version was accepted.
  6. Country and region are explicitly allowlisted after legal/compliance approval.
  7. Server-calculated score meets the program threshold.
  8. Daily paid-reward cap is not exceeded.
  9. A human reviewer approves the claim.
  10. The payout provider verifies the signature and honors the claim ID as an idempotency key.

GGX is separate

Purchased GGX is non-withdrawable utility credit for approved platform services. It does not represent cash, reward eligibility, a wager balance, or proof that a player earned anything. Utility purchases and reward claims use separate server paths.

Default behavior: fail closed.

When status is unavailable, configuration is incomplete, or a jurisdiction is absent from the allowlist, no reward should be assumed. Ordinary games remain playable without pretending the score is prize-safe.
